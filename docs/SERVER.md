# Сервер и ИИ

## Запуск

Нужен Node.js 24+. `npm install`, скопировать `.env.example` в `.env`, затем `npm run dev:all`. Если Vite уже работает: `npm run dev:server`. Клиент на localhost:5173 проксирует `/api` на 127.0.0.1:3001. Для локальной проверки готовой сборки: `npm run build && npm start`, открыть localhost:3001.

Сервер использует PostgreSQL через `pg`; подключение задаётся `DATABASE_URL`. Приватные слайды — в `.data/assets`. Ключи и файловые данные исключены из Git. Миграции и перенос старых данных описаны в [POSTGRES.md](POSTGRES.md), админка — в [ADMIN.md](ADMIN.md).


| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | Серверная строка подключения PostgreSQL; обязательна |
| `API_PORT` | Порт API, по умолчанию 3001 |
| `HOST` | Адрес привязки, по умолчанию 127.0.0.1 |
| `APP_ORIGIN` | Разрешённый origin интерфейса |
| `OPENAI_API_KEY` | Необязательный серверный ключ; без него работает разбор по правилам |
| `OPENAI_MODEL` | Модель Responses API с изображениями, PDF и Structured Outputs; по умолчанию gpt-4o-mini |
| `NODE_ENV=production` | Включает Secure для cookie; требует HTTPS |

Для ИИ вписать ключ в `.env` и перезапустить API. Затем войти в аккаунт и включить «Разбор с ИИ-наставником» при подготовке. Ключ не должен иметь префикс `VITE_`. 30 сентября 2026 ключ добавлен владельцем только в локальный `.env`: короткий реальный разбор ответа через существующий адаптер завершился успешно. Полное RU/EN-прохождение с ИИ и слайдами, квоты и учёт расходов ещё требуют отдельной проверки.

## Данные и API

JSON-запросы, cookie `pa_session` (HttpOnly, SameSite=Lax, 30 дней). Пароли хешируются scrypt; в БД хранятся только хеши токенов сессий входа. Слайды выдаются после проверки владельца. Межсайтовые записи и обычные формы отклоняются. Ограничены частота входов, ИИ-запросов и объём файлов.

| Маршрут | Назначение |
| --- | --- |
| `GET /api/health`, `GET /api/bootstrap` | Состояние API, аккаунт, проекты, история, черновик, доступность ИИ |
| `POST /api/auth/register`, `/login`, `/logout` | Регистрация, вход и выход |
| `PUT /api/profile` | Профиль пользователя |
| `POST /api/projects`, `PUT /api/projects/:id` | Создание и изменение личного проекта |
| `POST /api/history/import` | Явный импорт до 200 гостевых результатов; повтор не создаёт дублей, записи остаются неподтверждёнными |
| `POST /api/sessions`, `GET /api/sessions/:id` | Создание и чтение тренировки |
| `PUT /api/sessions/:id/draft` | Текст и положение интерфейса, без изменения баллов/ответов/вопросов |
| `POST /api/sessions/:id/assets`, `GET /api/assets/:id` | Загрузка и чтение приватных слайдов |
| `POST /api/sessions/:id/start`, `/analyze`, `/answer`, `/next`, `/complete` | Серверные переходы и начисление наград |
| `DELETE /api/sessions/:id` | Удаление незавершённой тренировки и её слайдов |

Изменения существующей тренировки требуют `If-Match: <revision>`. При устаревшей версии — 409. Клиент отправляет запросы последовательно; сервер блокирует параллельные изменения одной сессии через PostgreSQL advisory lock. Ответ отправляется после commit. Повторный `/complete` возвращает тот же результат. Один активный черновик на аккаунт. Перезагрузка не продлевает таймер; микрофон после восстановления включается только вручную.

## Как работает ИИ

После подтверждения транскрипта сервер отправляет текст и слайды в OpenAI Responses API. PDF передаётся как `input_file`, картинки — `input_image`. Ответ содержит краткий разбор, сильные стороны, улучшения, замечания по слайдам и пять вопросов с фиксированными идентификаторами. Вопросы появляются только после питча. Ответы пользователя разбираются отдельно; за тренировку допускается одно уточнение.

Используются [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) и [входные PDF](https://developers.openai.com/api/docs/guides/file-inputs). Zod проверяет структуру; непустые цитаты должны буквально присутствовать в исходном тексте. При тайм-ауте, отказе или некорректном ответе интерфейс явно показывает недоступность ИИ и сохраняет разбор по правилам. Автоматических платных повторов нет. `store:false` отключает сохранение Response для последующего получения; это не обещание отсутствия любых журналов у провайдера.

ИИ не выставляет баллы и не начисляет XP: это делает общая версия правил на сервере. Текст слайдов и питча рассматривается как материал, а не инструкции для сервера. У модели нет инструментов или доступа к БД. В технические логи приложения не записываются питчи, пароли, слайды, ответы провайдера или ключи.

Аудио не загружается на сервер приложения. Транскрипция пока браузерная (Web Speech API), не отдельный серверный сервис.

## Эксплуатационные границы

Это основа для локального/закрытого пилота на одном экземпляре API. PostgreSQL уже применяет версионные миграции; блокировки сессий находятся в БД. Файлы и лимиты частоты запросов пока локальны, поэтому несколько экземпляров API ещё не поддерживаются как готовая конфигурация.

Перед публичным запуском: HTTPS и корректный origin, резервные копии постоянного диска, восстановление пароля и подтверждение email, пользовательское удаление завершённых данных/аккаунта, мониторинг расходов и ошибок. Первая админка реализована; пока нет фоновой очереди ИИ и общего рейтинга; команды и каталог стартапов реализованы. Лимит входов учитывает адрес соединения; за reverse proxy он может быть общим — доверенную конфигурацию proxy нужно проработать при развёртывании.

Резервная копия: согласованный `pg_dump` и копия файлов `.data/assets` при остановленном API. Порядок переноса, ограничения файловых путей и возврат к SQLite описаны в [POSTGRES.md](POSTGRES.md). Для масштабирования нужны объектное хранилище, распределённые лимиты и очередь заданий.

Файлы: один PDF или до 20 изображений, до 20 МБ на файл, 40 МБ на тренировку, 100 МБ на пользователя. Проверяется сигнатура формата, не выполняется антивирусная проверка. Гостевые слайды и аудио после перезагрузки не восстанавливаются; аккаунт восстанавливает слайды. Удаление черновика не затрагивает завершённую историю.

Модуль сообщества, публичные маршруты, команды и модерация: [COMMUNITY.md](COMMUNITY.md). Правила входа и хранения секретов: [ACCESS.md](ACCESS.md).

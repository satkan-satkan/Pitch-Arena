# Подтверждение почты и восстановление доступа

## Что реализовано

После регистрации сервер ставит письмо подтверждения в отправку, если транспорт настроен. В окне аккаунта и профиле есть статус почты и повторная отправка. До подтверждения можно тренироваться и редактировать свои стартапы; список входящих приглашений скрыт, принять или отклонить приглашение нельзя. Существующие аккаунты после миграции остаются неподтверждёнными — владение их почтой раньше не проверялось. Данные и роль администратора сохраняются.

В окне входа есть «Забыли пароль?». Страница `/auth/reset-password` позволяет задать новый пароль. После успешного сброса все старые сеансы и ссылки аккаунта аннулируются; пользователь входит заново. Проекты, аватары, презентации и тренировки сохраняются. Владение адресом при успешном сбросе считается подтверждённым.

В профиле можно сменить пароль с проверкой текущего и выйти на всех устройствах. При смене пароля текущий браузер получает новую HttpOnly cookie, остальные сеансы завершаются. Выход со всех устройств включает текущий браузер. Удаление аккаунта — следующий отдельный этап: в этой версии его ещё нет.

## Подключение Brevo

Реализован [официальный API отправки транзакционных писем](https://developers.brevo.com/docs/send-a-transactional-email): серверный POST `/v3/smtp/email`, заголовок `api-key`, текстовое письмо. SMTP не используется. Письма содержат только служебную ссылку и инструкцию на RU/EN; проекты и слайды не отправляются провайдеру.

1. Зарегистрировать Brevo и подтвердить адрес отправителя в его интерфейсе. При использовании своего домена настроить подтверждение домена по инструкции Brevo.
2. Создать **API key**, не SMTP key.
3. Только в локальном `.env` задать `MAIL_PROVIDER=brevo`, `BREVO_API_KEY`, `MAIL_FROM_EMAIL` и при желании `MAIL_FROM_NAME`. Пример без секретов находится в `.env.example`.
4. Указать `APP_ORIGIN`: локально `http://localhost:5173`, для публичного сервера HTTPS-origin своего приложения без пути. Это источник всех почтовых ссылок; заголовок Host из входящего запроса для них не используется. Ссылка localhost откроется только на машине с приложением, поэтому для настоящего теста на другом устройстве нужен доступный HTTPS-адрес.
5. Перезапустить `npm run dev:server` (при первом запуске применится миграция `004_account_email.sql`). После настройки проверить реальную доставку на контролируемом адресе: подтверждение, повторную отправку, папку спам, сброс и вход с новым паролем. Успех API Brevo означает принятие письма провайдером, а не гарантированное попадание во входящие.

Без ключа или адреса отправителя `mailReady=false`: формы сообщают, что почта пока недоступна, а сервер отвечает `MAIL_UNAVAILABLE`. Ссылки не выводятся в консоль и не выдаются клиенту через API. `mailReady=true` означает наличие конфигурации, не проверку доставки или действительности ключа. При ошибке провайдера сервер пишет только обезличенное сообщение; содержимое ответа Brevo, адрес, ключ и токен не логируются.

## Ограничения и защита

- Случайный токен — 32 байта, в PostgreSQL хранится только SHA-256 hash. Подтверждение действует 24 часа, сброс — 30 минут. Новая ссылка того же типа отменяет предыдущую. Потребление выполняется в транзакции под блокировкой аккаунта; повтор и параллельное использование отклоняются.
- Ссылка содержит токен во fragment (`#token=…`), который не передаётся HTTP-серверу. Страница удаляет fragment из адресной строки, держит токен только в памяти, не сохраняет в localStorage/sessionStorage. После перезагрузки нужно снова открыть письмо. Политика Referrer — `no-referrer`.
- Открытие ссылки само по себе ничего не подтверждает. Для подтверждения нужен явный клик и вход в тот же аккаунт: почтовый сканер или пользователь другого аккаунта не расходует ссылку.
- Сброс возвращает одинаковое сообщение для существующего, неизвестного и заблокированного адреса. Поиск аккаунта и обращение к Brevo происходят в фоне после принятия запроса, поэтому задержка провайдера не выдаёт существование адреса.
- Пауза между запросами на один адрес — 60 секунд; до 5 запросов на адрес в час, 20 на сетевой IP в час, до 250 запросов на отправку за 24 часа для всего приложения. Неизвестные адреса тоже расходуют эти лимиты. Они хранятся в PostgreSQL и переживают перезапуск. Ограничение IP использует адрес сокета и не доверяет произвольному `X-Forwarded-For`; перед запуском за прокси нужно настроить доверенный источник IP, иначе весь прокси будет иметь общий лимит.
- Дополнительно до 20 операций восстановления/подтверждения/смены пароля в минуту на сетевой IP в процессе API. Количество ожидающих отправок ограничено. Пароли — 12–128 символов; остаётся scrypt с солью.
- Почтовые задачи находятся в памяти одного процесса. При корректной остановке сервер дожидается отправок (тайм-аут запроса Brevo — 10 секунд); при аварийном завершении неподтверждённые отправки могут потеряться — пользователь может повторить запрос. Автоматических повторных отправок и гарантированной очереди нет. После ошибки отправки токен этого письма удаляется. Для большого публичного запуска потребуется устойчивая очередь и мониторинг доставки; текущий механизм рассчитан на небольшой тест.

## Проверки

`npm run test:account-email` использует изолированную PostgreSQL и подставной транспорт: приватность, одноразовость, срок, чужой аккаунт, приглашения, нормализация email, замена ссылки, квоты после перезапуска, отзыв всех входов, конкурентный вход/сброс, отключённая и неудачная доставка, отсутствие ожидания провайдера в ответе API.

`npm run test:account-email:browser` проходит регистрацию, подтверждение на другом устройстве, сброс, несовпадение паролей, сохранность проекта, смену пароля и выход со всех устройств, повторное использование ссылки, RU/EN и телефон. Отчёт и скриншоты — `artifacts/v20-*`; в них только вымышленные данные и нет токенов.

`npm test` включает адаптер Brevo с подставным `fetch`, без реальных писем. Общие тесты создают `createApp` с отключённым транспортом, даже если на компьютере уже есть ключ. Реальный транспорт подключается только в `server/index.js`. Рабочая PostgreSQL не засеивается тестовыми аккаунтами.

Рекомендации по сценариям сверены с [OWASP Forgot Password Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html). Реальная доставка не проверена: ключ Brevo и отправитель пока не предоставлены.

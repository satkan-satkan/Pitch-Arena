# Админка владельца

Первая версия реализована. Вход — через обычный аккаунт Pitch Arena; пункт **«Админка»** появляется в боковом меню только после назначения роли. Проверка доступа выполняется и сервером, поэтому скрытие меню не является защитой само по себе.

## Назначение первого владельца

1. Зарегистрировать свой аккаунт через интерфейс игры.
2. На машине с API и настроенным `.env` выполнить:

```sh
npm run admin:grant -- owner@example.com
```

Заменить email на email своего существующего аккаунта. Команда не создаёт пользователя, не меняет пароль и не разблокирует заблокированную запись. Повтор для того же администратора ничего не изменяет. Назначение фиксируется как `owner.granted` с источником `server-cli` в журнале. После команды обновить страницу игры.

Публичная регистрация всегда создаёт роль `member`. Автоматического назначения администратора первому зарегистрированному пользователю нет. Email владельца не включается в исходный код или `.env.example`.

## Что доступно

| Раздел | Действия |
| --- | --- |
| Обзор | Количество пользователей, проектов, завершённых тренировок и черновиков; объём файлов; тип БД; наличие серверного ключа ИИ |
| Пользователи | Поиск по email, список с пагинацией, назначение/снятие роли администратора, блокировка/разблокировка |
| Проекты | Поиск, владелец, индустрия, дата создания и число тренировок; без раскрытия текста питча и приватных слайдов |
| Арены и инвесторы | Редактирование существующего каталога RU/EN, длительности/сложности арен и профилей инвесторов |
| Журнал | Кто, когда, какой объект изменил; прежние/новые значения, причина и версия каталога |

Изменения требуют причины. Блокировка аккаунта удаляет его активные входы, сохраняя данные. Администратор не может заблокировать себя или снять собственную роль; последний активный администратор защищён сервером. Пользовательская форма не может менять пароль, email или произвольные поля БД.

Арены можно закрывать для **новых** тренировок. Они остаются на карте, но вход запрещён сервером; уже начатые можно завершить. Стартовая арена «Свои люди» остаётся доступной. Отключение инвестора скрывает его из каталога отдельных инвесторов; участие в существующих панелях арен остаётся — эти настройки независимы.

Существующие карточки редактируются с проверкой `revision`. Одновременное изменение из другой вкладки возвращает 409 вместо тихого перезаписывания. Начатая серверная сессия хранит снимок арены и её панели; изменение каталога не переписывает её правила, имена и награды. Новые названия видны на карте, в подготовке и каталоге после обновления данных страницы.

Профили инвесторов описывают учебную симуляцию. Изменение карточки не создаёт партнёрство с реальным человеком и не подключает голос.

## API

- `GET /api/admin/overview` — агрегаты и состояние.
- `GET /api/admin/users?page=0&q=...`, `GET /api/admin/projects?page=0&q=...` — до 30 записей на страницу.
- `PUT /api/admin/users/:id` — `role`, `status`, `expectedRole`, `expectedStatus`, `reason`.
- `GET /api/admin/catalog` — текущие карточки и версии.
- `PUT /api/admin/catalog/arena/:id` или `/investor/:id` — `revision`, разрешённые поля в `data`, `reason`.
- `GET /api/admin/audit?page=0` — журнал без секретов.
- `GET /api/catalog` — каталог для игры, без административных данных.

Гость получает 401, обычный пользователь — 403. Запись и аудит проходят в одной транзакции PostgreSQL. Проверки роли повторяются внутри транзакции; административные изменения сериализуются через блокировку БД. Пароли, токены входа, API-ключи и тексты личных питчей не выдаются административным API.

## Границы версии

Пока нельзя добавлять/удалять арены и инвесторов, загружать новые портреты, публиковать стартапы, менять тарифы или выполнять платежи. Сначала появился рабочий редактор существующего каталога и управление доступом. Каталог стартапов и монетизация остаются следующими этапами. Отдельных ролей редактора и модератора пока нет.

«Ключ настроен» показывает наличие конфигурации, а не успешность последнего обращения к провайдеру. Живой OpenAI-вызов и публичное развёртывание по-прежнему отложены.

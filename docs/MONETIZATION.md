# Каталог и монетизация: основа следующего этапа

28 сентября 2026. Это архитектурное решение для дальнейшей разработки, не описание уже работающих платежей. Источник требований — дополнения IDEA-012–015 в [BACKLOG.md](BACKLOG.md).

## Разделение сущностей

| Сущность | Для чего нужна | Владелец/связь |
| --- | --- | --- |
| User | Вход, профиль, личная подписка | Человек |
| Team / TeamMember | Участники и роли | Команда; участник может состоять в нескольких |
| Startup | Существующий бизнес или идея | Команда либо отдельный пользователь |
| StartupListing | Опубликованная карточка, сайт, соцсети, категория и модерация | Startup |
| Project | Рабочие материалы и тренировки | Сейчас личный проект; позднее связь со Startup и участниками |
| Subscription / PlanVersion | Период подписки, набор возможностей и квоты | User |
| UsageEvent / UsageReservation | Учёт и резерв потребления ИИ | User + PitchSession + операция |
| PromotionOrder / Placement | Покупка и период рекламного размещения | Startup, плательщик отдельно |
| PaymentEvent | Платёж/возврат/изменение подписки у провайдера | Неизменяемый внешний ID события |
| AdminRole / AuditEvent | Права владельца и журнал изменений | User |

Личный проект не публикуется автоматически при создании команды. Первую карточку стартапа можно создать без команды; позднее передать управление команде явным действием. История питчей остаётся приватной. Подписка игрока и реклама стартапа имеют независимые права доступа и состояния оплаты.

## Первая вертикальная версия

1. **Реализовано:** перенести существующие аккаунты, проекты, сессии и ID в PostgreSQL; добавить версионные миграции. Сохранить текущий API и серверный расчёт наград. Для одноразового переноса использовать копию SQLite и проверить количества записей/владельцев, не удалять исходник.
2. **Реализовано:** добавить серверные роли и первую админку: обзор, каталог и журнал действий. Назначение первого владельца — серверная команда, не публичный параметр регистрации.
3. **Реализовано:** StartupListing с черновиком, отправкой на проверку и публикацией; соцсети — валидированные HTTPS-ссылки. Поддерживаются сайт, Telegram, X, LinkedIn, Instagram, YouTube, GitHub. Право на редактирование проверяется по владельцу/членству.
4. Добавить учёт использования модели и конфигурацию тарифов без приёма денег. Подставной провайдер в тестах позволяет проверить квоты до выдачи ключа OpenAI. В интерфейсе не показывать выдуманную себестоимость.
5. После замера расходов и выбора платёжного провайдера подключить подписку аккаунта, затем рекламные размещения каталога.

PostgreSQL 18.6 установлен у владельца в Postgres.app. Приложение уже переведено на PostgreSQL, мигратор проверен и выполнен локально. Есть первая админка с ролями, каталогом и аудитом. OpenAI-ключ и Railway отложены владельцем. Развёртывание не является условием разработки админки и каталога.

## Контроль расходов

На сервере идентификатор операции связывает резерв, вызов провайдера и запись результата. Резерв квоты создаётся атомарно до вызова: параллельные вкладки не могут потратить один остаток дважды. Отмена/ошибка освобождает резерв по определённым правилам; успешный повтор возвращает сохранённый результат. Тайм-аут с неизвестным результатом учитывается отдельно, чтобы не считать стоимость нулевой без доказательств.

В журнале: пользователь, тренировка, операция, провайдер, модель, входные/выходные/кешированные токены, длительность аудио при наличии, время, статус, версия цены и расчётная стоимость. Тексты питчей в финансовом журнале не нужны. Цены меняются отдельно от событий, старые расходы не пересчитываются молча. Фактический расход и списание пользовательской квоты — разные записи: даже неудачный платный вызов может иметь себестоимость.

Игроку показывать понятные лимиты разборов/минут и срок обновления квоты. Цена и размер пакетов определяются после измерения: транскрипция + анализ текста/слайдов + вопросы/ответы + озвучка + инфраструктура + платёжные издержки. Безлимит сейчас не закладывается.

## Оплата и продвижение

Обработчик webhook проверяет подпись и обрабатывает внешний ID события один раз в транзакции. Редирект с платёжной страницы не является подтверждением оплаты. Возврат, отмена, просрочка и смена тарифа имеют явные переходы. Пользователь не может назначить себе тариф или квоту через клиентский JSON.

У рекламы отдельные статусы: черновик → ожидает оплаты → проверка → запланирована → активна → завершена; отказ/возврат отдельно. При отсутствии трафика не обещать фиксированный результат. Платные места отмечать как рекламу; они не меняют игровые баллы или рейтинг по подтверждённым показателям.

Доходы стартапов для каталога сначала можно указывать как «со слов основателя». Для отметки «подтверждено» потребуется отдельная проверка источника. Тренировочный балл, выручка и рекламная позиция не объединяются в один рейтинг.

## Админка и редакция

В текущей версии администратор управляет доступом пользователей, каталогом арен и публикацией стартапов. Модерация стартапов реализована; конфигурация тарифных лимитов остаётся следующим этапом. Изменения содержат автора, время, объект, действие и основание. Пароли, API-ключи и полный текст приватных выступлений не показываются на сводной странице. Выдача/снятие роли и ручные поправки лимита журналируются отдельно.

Каталог инвесторов хранит проверенные источники, игровые настройки, локализацию, статус публикации и версию. Для голоса — провайдер, voiceId, разрешение, языки и резервная озвучка. Голос и API-ключи провайдера не встраиваются в публичный каталог. Добавление фонда не означает реальное партнёрство.

## Критерии готовности

- Регистрация не позволяет получить роль администратора; обычный пользователь получает 403 от административного API.
- Команда редактирует только свои карточки; публикация не раскрывает частные слайды.
- Повтор webhook и повтор запроса разбора не дают двойного списания/начисления.
- Параллельные запросы не превышают квоту; сбои провайдера оставляют объяснимый статус.
- Подписка пользователя работает независимо от рекламного заказа стартапа.
- Перенос на PostgreSQL сохраняет ID, историю, награды и принадлежность файлов; есть проверенный возврат к резервной копии.

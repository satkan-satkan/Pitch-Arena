# Доступ и секреты

Аккаунты регистрируются через лендинг или окно входа. Стандартных учётных данных нет. Пароль выбирает пользователь (12–128 символов); сервер хранит только salted scrypt hash в PostgreSQL. Токен входа находится в HttpOnly cookie, в БД хранится его SHA-256 hash. API не возвращает хеши паролей или токенов.

Ключи API и строка подключения хранятся локально в `.env`. В Git разрешён `.env.example` с примером конфигурации без секретов. `.env`, `.env.*` кроме примера, `.data/`, приватные ключи и типовые выгрузки БД исключены из Git. Секреты сервера нельзя помещать в `VITE_*`: такие значения могут попасть в браузерную сборку.

`npm run check:secrets` проверяет отслеживаемые и новые неигнорируемые файлы: запрещённые пути, узнаваемые форматы ключей и PostgreSQL URL с паролем. Значения секретов не выводятся. Это дополнительная проверка перед коммитом, не гарантия распознавания любых секретов и не сканер всей Git-истории. `git add -f` обходит ignore, поэтому локальные настройки и БД не следует добавлять принудительно.

Тесты содержат только вымышленные аккаунты и пароли для временных тестовых схем. Это не данные для входа в рабочую игру. В тестовых скриншотах могут быть адреса `example.com`.

Владельца админки назначают существующему аккаунту серверной командой `npm run admin:grant -- owner@example.com`, заменив пример на свой email. Публичной формы повышения прав нет. Пароль владельца не нужен для назначения роли. Секреты будущего Railway задаются через переменные среды сервиса; развёртывание пока не выполнялось.
